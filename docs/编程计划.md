> 进度记录在 [进度.md](进度.md)。每个编程会话开始时先读这三份材料，结束时更新进度。

## 0. 给每个编程会话的工作守则

1. **开始**
   - 读 `docs/需求.md`、`docs/编程计划.md`、`docs/进度.md`。
   - 运行 `git pull`，确认工作区干净。
   - 从进度表里找到第一个未完成的任务，接着做。
2. **一次只做一个任务**，按本计划给的「验收标准」逐条自检。原型里能直接看到的交互（尺寸、动效、文案），以原型为准。
3. **完成一个任务后**，按 `AGENTS.md` 的要求依次做：
   - 写测试（能写的都写）；
   - `cargo test` 和 `pnpm test` 全部通过；
   - `git commit`，写详细说明；
   - `git push` 并核对远端哈希；
   - 打出新的 Windows 安装包并安装到本机；
   - 在 `docs/进度.md` 打勾，并写一行记录。
4. **不中途停下来提问**：遇到需求里没写清的细节，按「最简单、最接近原型」的原则自己决定，把决定写进 `docs/进度.md` 的「决策记录」，继续做。只有以下情况才停下来找用户：
   - 需要用户的账号、密钥或付费操作；
   - 需要安装系统级软件，而用户还没有授权；
   - 需要真机交互才能判断对错的事项。
5. **会话快结束或上下文快满时**，先把手上的任务收尾，提交并更新进度，再结束。宁可少做一个任务，也不要留下半成品。
6. **不抄袭参考软件的代码**：交互可以参考，代码全部自己写。

## 2. 技术选型

| 层 | 选择 | 理由 |
|---|---|---|
| 应用框架 | **Tauri 2** | 包小、内存低，Rust 负责系统能力，以后能扩展到 Linux |
| 前端 | **Svelte 5 + TypeScript + Vite** | 运行时开销小，细粒度响应适合高频交互（拖选区、放大镜逐帧刷新）；多入口打包，对应多种窗口 |
| 样式 | CSS 变量（设计令牌）+ 少量组件 CSS | 直接复用原型里的 `.light` / `.dark` 令牌，不引入 UI 库 |
| 截屏 | Windows：DXGI Desktop Duplication / Windows Graphics Capture（`windows` crate）；跨平台备选 `xcap` | 多显示器、高 DPI、低延迟 |
| 全局快捷键 | `tauri-plugin-global-shortcut` | |
| 托盘 / 单实例 / 自启 | Tauri 内置托盘、`tauri-plugin-single-instance`、`tauri-plugin-autostart` | |
| 剪贴板 | `arboard`（图片和文字）；Windows 下用原生 API 写入「文件」格式，实现粘贴成文件 | 「粘贴成文件」需要 CF_HDROP |
| 窗口与元素识别 | Windows：`EnumWindows` + UI Automation（`uiautomation` crate） | 吸附窗口和控件，滚轮切换上下级元素 |
| 读取选中文字 | UI Automation TextPattern → 失败时模拟 Ctrl+C，再还原剪贴板 | |
| 本地 OCR | **ONNX Runtime（`ort` crate）+ PaddleOCR 模型**（PP-OCRv5 检测和识别、版面模型、SLANet 表格）；公式模型待评估 | 跨平台、离线、中日韩效果好 |
| HTTP 与流式输出 | `reqwest` + `eventsource-stream` | 三种接口格式都要支持流式输出 |
| 密钥 | `keyring` crate（Windows 凭据管理器 / Linux Secret Service） | |
| 历史数据库 | SQLite（`rusqlite`），图片文件放在磁盘上 | |
| 配置 | `serde` + JSON，`%APPDATA%\SnapMind\config.json`，带版本号和迁移 | |
| 表格导出 | `rust_xlsxwriter` | |
| 公式预览 | KaTeX（前端） | |
| 录屏 | Windows Graphics Capture 取帧 → ffmpeg（MP4）/ `gifski`（GIF）；声音用 WASAPI loopback | |
| 测试 | Rust：`cargo test`；前端：Vitest；OCR：自建评测命令行 | |
| 打包 | Tauri bundler → NSIS 安装包 | |

```
│  └─ snapmind-platform/     # 平台抽象 trait 及各平台实现：截屏、快捷键、取词、窗口枚举、录屏、剪贴板

│  ├─ src/
│  │  ├─ tokens.css          # 云母设计令牌（浅色 / 深夜 / 强调色）
│  │  ├─ lib/                # 共用组件：Button、Seg、Switch、Toolbar、Card、Hints、Magnifier…
│  │  └─ entries/
│  │     ├─ overlay/         # 截图编辑态
│  │     ├─ pin/             # 贴图窗口
│  │     ├─ card/            # 划词卡片 / 独立结果卡片
│  │     └─ settings/        # 设置窗口
│  └─ vite.config.ts
├─ models/                   # ONNX 模型（不入库，用脚本下载并校验哈希）
├─ scripts/                  # 下载模型、打包、安装、发布
├─ tests/fixtures/
├─ docs/
└─ design/prototype/
```

**约定**

- `snapmind-core` 不依赖 Tauri 和任何平台 API，保证可以单元测试。
- 前端只通过一层 `ipc.ts` 调用 Rust 命令，命令和事件的类型由 `specta` / `tauri-specta` 自动生成，避免前后端字段不一致。
- 所有 UI 组件只引用 `tokens.css` 里的变量，不写死颜色。

## 4. 关键设计决定

1. **截图「冻结帧」**：按下快捷键，先截下所有显示器，再显示遮罩窗口；遮罩窗口以截图为底图。这样框选时画面不会变化，取色也取的是真实像素。
2. **窗口预热**：启动时就创建好隐藏的遮罩窗口（每个显示器一个），按键后只需换底图并显示。目标是从按键到出现遮罩 ≤ 120 ms。
3. **标注渲染**：前端 Canvas 实时绘制。导出时在 Rust 里把底图和标注矢量数据按原始分辨率合成，保证高 DPI 下清晰。
4. **识别结果统一结构**：`OcrResult { blocks: [ { kind: paragraph | heading | table | formula | figure, bbox, lines: [ { id, text, bbox, conf } ] } ] }`。按段落和按行的文本、右键局部选择、原位覆盖、Markdown，全部从这个结构派生。
5. **备用链执行器**：在 `snapmind-core` 中实现 `run_chain(chain, request, timeout)`，按顺序尝试，返回结果和实际使用的后端。识别、翻译、一步到位三条链共用。
6. **流式输出**：后端通过 Tauri 事件把文字增量推给前端；前端用 `requestAnimationFrame` 合并刷新。
7. **设置即时生效**：配置修改后广播 `config-changed` 事件，所有窗口订阅（主题、快捷键、工具栏）。
8. **快捷键冲突**：注册失败时在设置页标红，并提示被哪个程序占用（能检测到时）。

## 7. 测试策略

- **单元测试**（`snapmind-core`、`snapmind-providers`）：路由、备用链、提示词渲染、配置迁移、历史清理策略。服务商用模拟 HTTP 服务器测试。
- **OCR 回归**：`snapmind-ocr eval` 在样本集上运行，指标下降时测试失败。
- **前端**：Vitest 测试状态逻辑（选区计算、提示避让、工具栏配置）。
- **手动验收清单**：每个里程碑结束时，按需求文档对应章节在真机上逐条检查，结果写进进度。

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| WebView 透明全屏窗口的显示速度 | 预热窗口；把截图作为底图提前传给前端（共享内存或 `asset://`） |
| 高 DPI 与多显示器坐标换算 | 统一使用物理像素，只在前端做一次缩放；写专门的坐标测试 |
| 段落合并阈值不稳 | 先建评测集再调参；阈值放进配置文件，便于调整 |
| 公式和表格本地模型效果不够 | 默认退回大模型，本地作为离线备选 |
| 长截图拼接错位 | 行哈希加模板匹配双重校验；匹配度不足时提示用户放慢滚动 |
| 录屏需要 ffmpeg | 随包附带精简版，或首次使用时下载 |
