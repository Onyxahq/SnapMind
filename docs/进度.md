## 决策记录

- **M0.1 前端工程布局**：`package.json` 放仓库根目录（Tauri CLI 从根目录运行最省事），Vite 配置放 `ui/vite.config.ts`，Vite 的 root 是 `ui/src/entries`，每种窗口一个子目录入口，窗口 URL 形如 `settings/index.html`。构建产物在 `ui/dist`。
- **M0.1 版本号单一来源**：版本号只写在根 `Cargo.toml` 的 `[workspace.package]`，各 crate 和 Tauri 都从这里继承；`tauri.conf.json` 不写 version。
- **M0.1 TypeScript 用 6.x**：svelte-check 4.7 的 peer 依赖还不支持 TS 7，先锁 `^6`，等 svelte-check 跟上再升。
- **M0.1 应用标识**：`app.snapmind.desktop`。应用图标自己画（`design/icon/snapmind.svg`：蓝色圆角方块 + 取景框四角 + 四角星），用 `tauri icon` 生成各尺寸，只保留桌面端需要的文件。
- **M0.1 不入库**：`src-tauri/gen/`（Tauri 构建时自动生成的权限描述）。
- **M0.1 发布构建**：release 配置开 LTO、`opt-level = "s"`、`panic = "abort"`、strip，优先控制安装包体积（预算 ≤ 25 MB）。
- **M0.2 启动方式**：手动打开（开始菜单、双击）时显示设置窗口；开机自启带 `--autostart` 参数，只进托盘不弹窗。重复启动时由单实例插件聚焦已有的设置窗口。
- **M0.2 托盘交互**：左键单击 = 截图（和快捷键同一个动作，M1.1 前为空操作）；右键菜单：截图 / 贴图 / 设置… / 开机自启（勾选项）/ 退出，截图和贴图后面用制表符显示快捷键。开机自启的勾选状态每次都以系统里的实际状态为准。
- **M0.2 关闭窗口**：设置窗口点关闭只隐藏，不退出；退出只走托盘菜单。设置窗口在配置里预先创建为隐藏，打开时无需再加载。
- **M0.2 窗口管理模块命名**：`src-tauri/src/wm.rs`，不叫 `windows`，避免和以后引入的 `windows` crate 重名。全局动作集中在 `actions.rs`，托盘和快捷键共用。
- **M0.3 令牌作用域**：`data-theme` / `data-accent` 一般设在 `<html>`，但选择器不限定 `:root`，任意元素都能局部换一套令牌（演示页靠这个并排展示两种模式，以后的贴图、卡片窗口也可以用）。明暗切换的 300ms 颜色过渡只在第一次上色之后才开启，窗口打开时不闪。
- **M0.3 字体**：不随包附带 Inter / Noto Sans SC（控制包体积、离线可用），字体栈为 Inter → Segoe UI Variable → Segoe UI → Noto Sans SC → 微软雅黑；等宽为 JetBrains Mono → Cascadia Mono → Consolas。
- **M0.3 组件取舍**：按钮高度统一用设置页的 32px；IconButton 默认 30px（需求 3.6 的工具条按钮尺寸），设置页传 28。Seg 的选中块用滑动动画（开关曲线 220ms）而不是原型里的瞬间切换，更跟手；Switch 按住时滑块拉长、松手回弹。Select 用原生下拉（列表跟随 color-scheme 自动适配明暗），只自绘外框和箭头。额外加了 Row（卡片里的一行设置），设置页大量复用。
- **M0.3 演示页**：`ui/src/entries/gallery/` 只在开发服务器里可访问（`/gallery/index.html`），不加入生产构建入口。`.claude/launch.json` 记录开发服务器配置，便于在内置浏览器里预览。
- **M0.3 动效实现**：Svelte 的 JS 过渡需要缓动函数，自己实现了 cubic-bezier 求解（`$lib/motion.ts`，有单测），让 JS 过渡和 CSS 用同一组曲线。
- **M0.4 配置更新协议**：前端只有 `config_get` 和 `config_update(patch)` 两个命令。补丁是 JSON Merge Patch（RFC 7386），Rust 端合并后按结构整体反序列化校验，非法值直接拒绝、文件不动；内容没变时不写盘也不广播。`version` 不能通过补丁改。
- **M0.4 配置文件的健壮性**：写入用「临时文件 + 改名」保证原子性；读到损坏的 JSON 时改名为 `config.broken-<时间戳>.json` 再用默认值重建，程序照常启动。缺字段取默认值，未知字段忽略。没有 `version` 视为第 1 版；版本号比程序新时宽松读取、不降级版本号。
- **M0.4 配置目录**：用系统配置目录拼 `SnapMind`（Windows `%APPDATA%\SnapMind`，Linux `~/.config/SnapMind`），与需求第 10 节一致，不用 Tauri 默认的 identifier 目录。
- **M0.4 主题即时生效**：每个窗口启动时 `startConfig()` 先读配置、上主题再挂载界面（不闪默认主题），之后订阅 `config-changed`。Rust 端同时把所有窗口的原生主题设成对应明暗（跟随系统时为 None），标题栏也一起变。
- **M0.4 浏览器假实现**：`ipc.ts` 在没有 Tauri 时用内存配置和本地订阅模拟命令与事件，开发页在普通浏览器里也能完整交互。
- **M0.5 版本号规则**：语义化版本。正式发布（M11 完成）前用 `0.<里程碑号+1>.<该里程碑已完成任务数>`，每完成一个任务升一次：M0 全部完成 = 0.1.5，M1.1 完成 = 0.2.1，依此类推到 M12（0.13.x）。首个公开发布版为 1.0.0，之后按常规语义化版本（修复升 patch、新功能升 minor、不兼容改动升 major）。版本号只改 `Cargo.toml` 的 `[workspace.package]` 和 `package.json`，由 `pnpm release` 同步修改，安装包文件名和 exe 的产品版本都随之变化。
- **M0.5 打包脚本用 Node 写**：`scripts/release.mjs`，跨平台（M12 Linux 也能复用打包部分），也避开了 Windows PowerShell 5 的编码问题；只有查进程、读 exe 版本这类 Windows 专属的小操作调用 PowerShell。覆盖安装前只结束安装目录里的 snapmind.exe（连同 WebView2 子进程），不影响开发中的调试实例。安装包超过 25 MB 预算时给出警告。
- **M1.1 截屏方式**：用 GDI `BitBlt`（带 `CAPTUREBLT`，分层窗口也能抓到），每个显示器一个线程并行抓。2560×1440 约 35 ms，够用且简单；DXGI / WGC 留到录屏（M9.2）再上。进程是每显示器 DPI 感知，抓到的就是物理像素。
- **M1.1 截图传给前端**：抓下来的像素前面加 54 字节文件头就是 BMP，存在内存里，通过自定义协议 `snapframe`（`/<显示器序号>`）提供给遮罩页面，省掉 PNG 编码（4K 要上百毫秒）。响应带 `Access-Control-Allow-Origin: *`，以后画布能读像素做取色和放大镜。alpha 统一置 255，避免浏览器把 GDI 留下的随机 alpha 当真。
- **M1.1 遮罩先出现，冻结帧随后补上**：遮罩窗口是透明的，帧传过来之前透出的就是真实桌面，和冻结帧一模一样，所以收到事件的第一帧就显示遮罩（42–47 ms），冻结帧解码好再无缝垫到下面（约 200 ms，主要花在 14 MB 数据经 WebView 传输）。性能预算按「遮罩出现」计。
- **M1.1 遮罩窗口不隐藏，而是停在屏幕外**：隐藏几秒后的 WebView 再显示，第一帧要多等约 140 ms（合成被挂起）。所以遮罩窗口启动后一直「可见」，停在 (-30000, -30000)，截图时移到对应显示器，结束时移回去。配套：设为工具窗口（不进任务栏和 Alt+Tab）、不激活地显示（不抢焦点）、关掉系统窗口过渡动画；所有窗口的 WebView2 统一加启动参数关闭 Chromium 遮挡检测和后台降频（同一进程里各窗口的参数必须一致，设置窗口在 tauri.conf.json 里写了同一串）。
- **M1.1 计时方法**：前端在遮罩真正画出后（事件后第二个 rAF）把自己的 `Date.now()` 回报给 Rust，与按键时刻相减。不能用「Rust 收到回报的时间」：当时主线程正忙着传输截图，回报会排队 150 ms，测出来的数偏大。
- **M1.1 快捷键**：先写死 `Shift+F1`（`actions::CAPTURE_SHORTCUT`），注册失败（被别的程序占用）只记日志不影响启动；改为可配置、冲突标红在 M10.1 做。截图中再按快捷键会被忽略。M1.1 只做了 `Esc` 直接退出，逐级退出规则在 M1.6。
- **M1.1 前端日志**：新增 `ui_log` 命令和 `$lib/log.ts`，各窗口的未捕获错误、Promise 拒绝都转发到 Rust 的 stderr（隐藏窗口没法开开发者工具）。M11.2 改为写滚动日志文件。
- **M1.1 多显示器与缩放**：本机只有一块屏，多屏和混合缩放的坐标换算靠 `$lib/geometry.ts` 的单元测试覆盖（4K@150% + 1080p@100% + 负坐标竖屏@125%），真机验证列入待点验。
- **M1.2 选区坐标**：选区存为所在显示器截图的物理像素整数，鼠标 CSS 坐标乘缩放后取整；显示时再除回去。方向键微调的 1px 是截图里的 1 个像素。标签里的 x,y 是虚拟桌面物理坐标（显示器原点 + 选区偏移）。
- **M1.2 交互细节**：按下后移动不足 3 CSS 像素算单击；单击选中整个显示器（M1.3 起改为选中鼠标下吸附到的窗口或控件）。控制点和边的命中容差 7 CSS 像素，优先级：控制点 > 边 > 内部移动。拖控制点越过对边时选区翻转，不会出现负宽高；移动和调整都夹在显示器内，选区不跨显示器。在某块屏上新建选区会广播 `overlay:claim`，其他屏的选区作废，同一时间只有一个选区。右键：有选区时取消选区，没有时退出截图。
- **M1.2 外观**：描边用 `box-shadow` 画在选区外侧 1.5px，不遮住被截内容；遮罩用 `clip-path: polygon(evenodd, …)` 挖洞，拖动时逐帧跟手、不加过渡；新建拖动过程中不显示控制点。标签用 `white-space: pre` 保留坐标与尺寸间的三个空格。
- **M1.2 浏览器调试**：遮罩页在普通浏览器里打开时自动生成一张假截图（`devFrame.ts`），后续的放大镜、提示、工具条都能直接在内置浏览器里调。
- **M1.3 吸附的数据来源**：遮罩盖在最上面，不能直接问系统「鼠标下是什么」。所以按键时先拍顶层窗口快照（`EnumWindows` 的 Z 序，外框取 `DWMWA_EXTENDED_FRAME_BOUNDS` 去掉隐形缩放边框；跳过隐藏、最小化、被 cloak、鼠标穿透、本进程以及 `Shell_SystemDim` 这类系统变暗层），悬停时用快照找到鼠标下的顶层窗口，再对它做 UI Automation 查询。快照与冻结帧是同一时刻的。
- **M1.3 UI Automation 查询**：专用线程（COM 多线程套间）+ 缓存请求（一次跨进程调用取回外框和是否在屏幕外），从窗口沿「包含鼠标点」的路径深度优先往里走：同层候选按面积从小到大，某个候选下面没有子元素就回溯换下一个（Electron 窗口里和内容区一样大的 `Intermediate D3D Window` 空层会挡路），每层最多试 3 个、最多 24 层、每次查询限时 150 ms；请求只处理最新的一个。和上一层一样大的元素去掉。实测 20–30 ms。
- **M1.3 交互**：没有选区时悬停就吸附，默认高亮最内层；滚轮向上往外一层、向下往里一层；鼠标移动后如果当前高亮的矩形仍在新链里（例如已经滚到整个窗口、鼠标还在窗口里）就保持该层，否则回到最内层。单击选中高亮框；桌面空白处（链为空）单击选整屏。高亮框和遮罩挖洞用 120ms「吸附」曲线滑动，选区拖动时仍逐帧跟手。右键取消选区后回到悬停吸附。
- **M1.3 已知限制**：Chromium / Electron 只在辅助功能模式下才把网页内容暴露给 UI Automation，这类窗口内部只能吸附到窗口一级（原生 Win32 / WinUI 控件、桌面图标、任务栏按钮可以吸附到单个元素）。需求里的「吸附段落」等 M4 有本地 OCR 后用检测框补上。
- **M1.4 放大镜的数据来源**：直接把已解码的冻结帧 `<img>` 的一小块画到放大镜画布上（关掉平滑），中心像素的颜色用 1×1 画布取样，不把整张截图读成像素数组（2560×1440 就是 14 MB）。冻结帧解码好之前不显示放大镜。信息栏两种模式下都用深色（看的是截图本身的颜色，不随主题变）。
- **M1.4 显示规则**：框选前后都显示；移动选区时隐藏（标注、长截图、录屏时的隐藏随对应任务接入）；鼠标离开这块屏时隐藏。截图事件里带上按键时的鼠标位置，放大镜一出现就能定位，不必等鼠标先动一下。
- **M1.4 快捷键**：`P` 循环 HEX → RGB → HSL，选择记入配置 `capture.colorFormat`（下次截图沿用）；三种格式都是可直接粘进 CSS 的写法：`#2563EB`、`rgb(37, 99, 235)`、`hsl(221, 83%, 53%)`。`C` 复制当前格式的颜色值并弹出轻提示。`W A S D` 移动的是**系统鼠标**（Rust `SetCursorPos`），系统会照常发出鼠标移动，所以正在拖的选区、控制点也能逐像素精确移动。带 Ctrl / Alt / Shift 的组合键不触发这几个单键（留给 `Ctrl+C`、`Shift+C` 等）。
- **M1.4 剪贴板走 Rust**：WebView 的 `navigator.clipboard` 在没有焦点或权限时会被拒绝，改用 Rust 的 `arboard` 写系统剪贴板（`clipboard_write_text` 命令）；M1.6 的图片和「粘贴成文件」也放在同一个模块。
- **M1.5 提示内容只列能用的操作**：原型里有选区时的提示包含复制、贴图、识别、翻译等快捷键，但这些还没实现。提示面板只列已经能用的，每个后续任务实现新快捷键时顺手补进 `hintsFor`，不让提示里出现按了没反应的键。
- **M1.5 避让与淡出**：面板按实际渲染尺寸计算位置（不估高度），默认左下角，被选区挡住时依次试左上、右下、右上，四角都挡（如全屏选区）时取重叠面积最小的角；只避让真正的选区，不避让悬停吸附的高亮框（否则面板会跟着鼠标乱跳）。光标进入面板外扩 24px 的范围时面板淡到 12% 不透明，移开恢复，避免挡住要截的内容。换角时位置平滑过渡。
- **M1.5 配置**：`capture.showHints` 默认 true；`CaptureConfig` 改为手写 `Default`，旧配置里只有 `colorFormat` 时提示仍默认显示（有单测）。设置窗口先加一个「截图」卡片放这个开关，完整设置页在 M10.1。
- **M1.6 复制放三种格式**：`CF_DIB`（32 位自下而上，几乎所有程序都认）+ 注册格式 `PNG`（浏览器、Office 优先用，无损）+ `CF_HDROP` 指向 `%TEMP%\SnapMind` 里按文件名模板生成的 PNG（资源管理器粘贴得到文件），并设 `Preferred DropEffect = 复制`。聊天软件粘贴图片文件时按图片发送，所以三种并存不会变成发文件。临时文件启动时清理一天以前的。用原生 Win32 剪贴板 API 一次写入（arboard 不支持多格式），被占用时重试 10 次。
- **M1.6 导出流程**：Rust 从会话里的冻结帧裁出选区后**立刻**结束截图（遮罩移走），编码和写剪贴板 / 写文件在后台线程完成，界面不等编码。PNG 剪贴板文件用快速压缩，保存用默认压缩；JPG / WebP 质量 1–100（WebP 用 libwebp）；尺寸与选区不同时缩放（缩小用 Lanczos3）。导出逻辑在 `snapmind-core::export`，标注合成（M2.3）接在裁剪之后。
- **M1.6 保存窗口**：左边按比例预览，右边：目录（可直接编辑）+ 打开目录、常用位置（桌面 / 图片 / SnapMind / 用户添加的）、文件名 + 格式三段切换 + 格式说明、宽高 + 锁定比例、质量滑块（仅 JPG / WebP）、预计大小（参数停 250ms 后真实编码一次，所以是准确值）、完整路径。Enter 保存、Esc 只关窗口。保存窗口里文件重名时自动加 (2)，不会覆盖；系统另存为由对话框自己确认覆盖。上次用的格式、质量、目录记入配置。系统对话框挂在遮罩窗口下，显示在遮罩之上。
- **M1.6 Ctrl+S 行为**：配置 `save.ctrlS` = window（默认）/ system / direct，设置页「截图」卡片可选；直接保存按 `save.format`、`save.quality` 和文件名模板存到默认目录（空 = 图片\SnapMind）。文件名模板默认 `SnapMind_{yyyyMMdd_HHmmss}`，花括号里认 yyyy MM dd HH mm ss SSS，非法字符换成下划线，设置页可改。
- **M1.6 没有选区时**：Enter / Ctrl+C / Ctrl+S 作用于悬停高亮的元素，没有高亮时作用于整屏——按快捷键、回车就能快速截一个窗口。
- **M1.6 Esc 逐级退出**：目前的层级是 保存窗口 → 截图；弹层、长截图 / 录屏、结果卡片、标注随后续任务插入这条链。保存窗口打开时，编辑态的单键快捷键（WASD、P、C、H…）不生效。
- **M1.6 贴图占位**：工具条有贴图按钮、Ctrl+T 有响应，但只弹出「贴图功能还在开发中」，不结束截图；M3.1 实现。
- **配置容错**：配置文件开头的 UTF-8 BOM 不再导致「配置损坏」（记事本、PowerShell 改过的文件常带 BOM），有单测。
- **M2.1 标注数据**：矢量形状存所在显示器截图的**物理像素**坐标和线宽（CSS 粗细 × 缩放），导出时可以按原始分辨率重画（M2.3）。撤销历史记录「添加若干形状 / 删除若干形状」两种操作，撤销就是反向执行；橡皮擦一笔划过的所有形状算一步，撤销时按创建顺序放回。序号取现有最大值 + 1，撤销或擦掉后自然回退。
- **M2.1 交互**：进入标注模式（空格、1–7、点工具按钮；还没有选区时先选中悬停元素或整屏）后，选区锁定不能移动 / 调整，控制点和放大镜隐藏，拖动只在选区内绘制（点被夹到选区内，画面也裁到选区内）。空格或右键退出标注，标注保留。矩形 / 箭头按住 Shift 约束为正方形 / 正圆 / 45° 直线；太短的矩形和箭头（< 3px，误触）不保留；序号单击即放下。画标注时工具条保持显示，不随每一笔闪烁。已有标注时右键不再取消选区（免得标注丢失，未保存标注的退出确认在 M2.3）。
- **M2.1 工具条与样式**：工具按钮按快捷键顺序排列（1 矩形、2 画笔、3 箭头、5 序号、7 橡皮擦；4 文字、6 马赛克在 M2.2 加入，按 4、6 暂时无反应），带样式的工具右侧有小箭头打开弹层，再点一次当前工具也能开关弹层；弹层放不下时朝上开。每个工具各自记住子类型、颜色、粗细，默认红色、中档粗细；遮罩窗口常驻，所以整个运行期间都记得（不写配置）。
- **M2.1 绘制效果**：画笔经过相邻两点中点画二次曲线，并丢掉过密的点；荧光笔 38% 不透明、4 倍粗、方头；箭头的杆子只画到箭头根部，粗线也不会从尖端冒出来；序号为实心圆加白色数字（白色序号用深色数字）。
- **M2.2 文字标注**：单击空白处新建（第一行的竖直中心落在点击处），单击已有文字重新编辑，按住拖动则移动（移动超过 3px 才算拖动）。编辑框是放在原位的 textarea，字号颜色和最终效果一致，`field-sizing: content` 随内容伸缩；回车换行，Esc / Ctrl+Enter / 点别处提交；打字时编辑态快捷键不生效。提交时去掉末尾空白，空文字丢弃（重新编辑的文字被清空则删除），量出文字框尺寸存进形状供橡皮擦和点选使用。编辑时改颜色 / 字号立即作用到正在编辑的文字。三档字号 16 / 22 / 30（CSS 像素）。
- **M2.2 撤销模型补充**：新增「替换」操作（改文字、移动文字各算一步），撤销时换回修改前的版本。
- **M2.2 马赛克 / 模糊**：都基于冻结帧的真实像素绘制，跟着区域实时预览。马赛克：区域按方块边长缩小到小画布（每块取平均色）再关闭平滑放大；模糊：画布 `filter: blur()`，多取一圈像素再裁回区域，边缘不发虚透明。三档强度：方块边长 / 模糊半径 6 / 10 / 16（CSS 像素）。弹层里马赛克没有颜色选项，粗细一栏叫「强度」，文字叫「字号」。按 Shift 拖成正方形。橡皮擦对马赛克整块区域都算命中。
- **M2.2 焦点问题**：在遮罩上点击会把焦点切到页面，刚建好的文字框随即失焦、被当成空文字丢掉。标注模式下按下鼠标时阻止默认的焦点切换，编辑框也在下一帧才聚焦。
- **M2.3 合成方案（与编程计划不同）**：计划写的是「Rust 按矢量数据重画」。实际改为前端用屏幕上同一套绘制代码，在 1 画布像素 = 1 截图物理像素的离屏画布上把标注层画出来，取 RGBA 像素经二进制请求体上传，Rust 在裁剪后、缩放编码前按 source-over 叠上去。理由：只有一套渲染器，文字字体、马赛克 / 模糊、荧光笔效果和屏幕上完全一致（所见即所得），按物理像素渲染所以 4K 下边缘同样清晰；Rust 端不必引入字体排版和模糊滤镜。
- **M2.3 传输优化**：最初用 `convertToBlob` 编码 PNG，500×300 的标注层也要约 1 秒（Chromium 的 PNG 编码路径很慢）；改为 `getImageData` 取原始像素（同步、毫秒级），并且只上传不透明像素的外框（带相对选区的偏移），上传量与标注面积成正比。实测全屏选区加一个序号：渲染 13 ms、上传 5 ms。标注层在每次复制、保存、打开保存窗口（预计大小要算上标注）前上传，尺寸或位置超出选区时 Rust 拒绝叠加，避免错位。
- **M2.3 退出确认**：有标注且没有复制 / 保存时，Esc 退出、工具条退出按钮、右键退出都会弹出确认框；Enter 放弃并退出、Esc 取消回到截图；勾选「不再询问」写入配置 `capture.confirmDiscard = false`，设置页「截图」卡片有同一个开关。复制、保存等交出结果的动作会结束截图，不需要确认。确认框是逐级退出链上的一级。
- **真机自动化测试**：系统级变暗层挡住了模拟鼠标后，改用 WebView2 远程调试端口：环境变量 `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=9333` 启动调试版，`scripts/cdp-drive.mjs` 通过 Chrome DevTools Protocol 向遮罩页面派发鼠标、键盘、输入法文字并执行脚本，再用 PowerShell 读剪贴板核对结果。启动时 stdout / stderr 都要重定向，否则子进程继承调用方的管道，调用方会一直等它退出。
- **M3.1 贴图窗口**：每张贴图一个窗口 `pin-<id>`（透明、无边框、置顶、不进任务栏、关闭系统过渡动画），图片按 1:1 物理像素出现在原截图位置。透明窗口不能用系统阴影，所以窗口比图片大一圈 10 CSS 像素的透明边距，在边距里画阴影；悬停时显示 2px 强调色描边和「缩放 · 不透明度」标签。图片数据（带标注的合成结果）存在 Rust 内存里，经 `snapframe` 协议的 `/pin/<id>` 提供（BMP）。窗口先隐藏创建，页面解码好图片后再显示，避免透明窗口闪空白。
- **M3.1 交互**：按下后移动超过 3px 才调用系统的窗口拖动（`startDragging`，最跟手），所以双击仍能关闭；滚轮每格 10%，Rust 以鼠标为锚点同时改窗口位置和尺寸（10%–800%），放大到 200% 以上改为像素化显示；Ctrl+滚轮每格 10% 调不透明度（10%–100%，CSS 实现）；Ctrl+0 以窗口中心回到 100%。缩放比例不单独记录，总是由窗口实际宽度推算，拖到不同缩放的显示器、被系统改了尺寸也不会错乱。
- **M3.1 鼠标穿透**：穿透后窗口收不到鼠标和键盘，所以 `Ctrl+Shift+X` 注册为全局快捷键（有贴图时才注册、没有贴图时注销）：焦点在贴图上时让它穿透，否则取消所有贴图的穿透。**本机的 Ctrl+Shift+X 已被别的程序占用**，注册失败时退而求其次：按键落到获得焦点的贴图窗口里由页面开启穿透，托盘菜单新增「取消贴图的鼠标穿透」（有贴图在穿透时才可用）负责取消。快捷键冲突的提示在 M10.1 的快捷键设置里做。
- **M3.1 关闭**：双击、Esc、Alt+F4 都会销毁窗口并释放图片；写入历史在 M3.4。
- **M3.2 工具条是独立窗口**：所有贴图共用一个预先建好的 `pintools` 窗口（透明、不抢焦点、不进任务栏），悬停到哪张贴图就由 Rust 摆到它的图片下方右对齐，下方放不下就放上方（此时「更多」菜单朝上开）。不放进贴图窗口里：那样每张贴图下面都要预留一条透明区域挡住桌面点击。工具条页面用 ResizeObserver 报告自身尺寸，Rust 据此调整窗口大小（菜单展开时变高）。贴图移动、缩放时工具条跟着走。
- **M3.2 防丢失**：工具条窗口靠贴图一侧留 8px 透明连接区；贴图悬停、工具条悬停、菜单打开三者任一成立就显示，都不成立时延迟 450ms 隐藏（用状态版本号判断期间是否又有悬停）。工具条不抢焦点，点按钮后贴图里的快捷键照常可用。
- **M3.2 工具条按钮**：只放已经能用的——复制、保存、更多、关闭；「更多」里是不透明度滑块（10%–100%，与 Ctrl+滚轮同步）、鼠标穿透、缩放到 100%。翻译、识别文字、Markdown、标注、公式、表格、自定义工具条随对应任务加入。工具条把动作作为事件发给对应的贴图窗口，由贴图页面执行。
- **M3.2 贴图复制 / 保存**：复制与截图复制同一套（位图 + PNG + 临时文件）；保存弹系统另存为对话框（挂在贴图窗口下），默认目录、文件名模板与截图一致，格式按选的扩展名，质量用配置里的值；保存后贴图保留。贴图里也有 Ctrl+C、Ctrl+S。
- **M3.2 贴剪贴板（Shift+F3）**：优先取图片（arboard，支持 DIB），其次取文字；图片以鼠标为中心按 1:1 贴出。文字由贴图页面按当前主题排成卡片（15px 字号、24px 行高、最宽 460px、16px 内边距；中日韩逐字换行，拉丁文在空格处换行，最多 200 行），按物理像素渲染后交回 Rust 作为贴图图片，卡片左上角在鼠标附近；复制文字卡片时复制原文。
- **M3.3 标注控制器**：把截图编辑态里的标注状态与交互（工具、样式、文档与撤销、画 / 擦 / 文字编辑与拖动、马赛克）抽成 `$lib/annotator.svelte.ts` 的 `Annotator` 类，截图和贴图各持有一个实例；宿主只负责坐标换算（截图 = 本屏截图像素，贴图 = 贴图图片像素）、提供夹点函数和每 CSS 像素对应的画布像素（线宽、字号据此换算）。标注工具按钮和样式面板也抽成共用组件 `$lib/annot/ToolButtons`、`ToolProps`。控制器有 6 个单元测试。
- **M3.3 贴图标注**：贴图页面自己持有标注并画在图片上（图片像素坐标，缩放后仍对齐）；工具条窗口在标注模式下显示标注工具，并通过 `pin_keep` 一直显示（不随悬停隐藏）。工具条与贴图之间用事件互通：贴图推送标注状态（工具、样式、能否撤销），工具条发回选工具 / 改样式 / 撤销 / 完成。标注模式下拖动是绘制、双击不关闭、滚轮缩放照常；1–7、Ctrl+Z、空格 / Esc 退出。
- **M3.3 贴图导出带标注**：复制 / 保存前贴图页面按图片原始分辨率渲染标注层（只取不透明部分），上传给 Rust 存在贴图上，导出时叠加（与截图同一套 `composite_over`）。带标注的文字卡片复制图片而不是原文。
- **M3.4 历史库**：`snapmind-core::history`，SQLite（rusqlite 内置编译）放在配置目录的 `history/history.db`，原图 `images/<id>.png`、缩略图 `thumbs/<id>.jpg`；数据库只存元数据和识别文字（便于搜索），图片在磁盘上（按空间清理时优先删图片，M10.3）。用 `PRAGMA user_version` 记结构版本，翻译历史在 M6.4 加表。写文件失败时回滚那一行，不留半条记录。搜索用 LIKE（转义 % 和 _，ASCII 不区分大小写）。放在 `%APPDATA%\SnapMind` 而不是安装目录 `%LOCALAPPDATA%\SnapMind`，避免卸载时被一并删掉。
- **M3.4 关闭即入库**：贴图关闭时先取带标注的合成图，再在后台线程编码和写库，关闭本身不等待。贴图页面在关闭前、退出标注模式时都会上传标注层，所以 Alt+F4 直接关闭也能带上标注。文字卡片排版完成前（1×1 占位图）就关掉的不记。历史库打不开时只记日志，其他功能照常。查询命令 `history_pins` 先提供给 M10.3 的历史页面。
- **M4 暂缓**：本地 OCR 需要下载 ONNX Runtime（`ort` 从 cdn.pyke.io 下载，约 15–20 MB）和 PP-OCRv5 mobile 检测 / 识别模型（约 5 MB + 16 MB）。下载第三方文件要先得到用户同意，已经提问，回复前先做不依赖下载的 M5，得到同意后回到 M4.1。
- **M5.1 配置结构**：`providers` 是数组，元素 `{ id, kind, name, baseUrl, models: [{ id, tags, enabled }] }`；合并补丁对数组整体替换，前端每次提交完整列表。`id` 同时是系统凭据库里 Key 的账户名（服务名 `SnapMind`），内置服务商用种类名，自定义服务可以加多个（custom、custom-2……）。Key 绝不回传前端，只回答「有没有」；输入框不回显，已保存时显示锁形图标和「输入新的 Key 可替换」，清空输入框不会误删，移除服务商时才删 Key。
- **M5.1 交互**：填好 Key（回车或失焦）就自动获取模型列表——这一步顺带验证 Key，用户不用再点；Ollama 添加后直接获取。「测试连接」只连不改列表，「获取模型列表」把新列表并进来：已有模型保留勾选和改过的标签，新模型默认不勾选，服务商不再提供但勾选着的保留（可能是手动添加的）。勾选的排在最前；模型超过 8 个出现筛选框（OpenRouter 有几百个）。移除要点两次（3 秒内）。
- **M5.1 标签**：按模型名推断，用户可在每行点标签修改（未打上的标签悬停这一行才显示）。「视觉」和「文本」互斥且必有其一（视觉模型本来就能处理文本，识别和一步到位只认「视觉」）；Claude、Gemini 全系、gpt-4o / 4.1 / 5、带 vl / vision / llava / pixtral 的标视觉；名字里有 reason / thinking / r1 / o1 / o3 / o4 / qwq 的加「推理」；Ollama 的模型加「本地」。
- **M5.1 网络**：reqwest 用 rustls（不依赖系统 OpenSSL，Linux 版也一样），获取模型列表超时 15 秒；401 / 403 统一提示 Key 无效，其他错误尽量取出服务商返回的 `error.message`。
- **M5.2 调用形式**：`stream_chat(endpoint, request, on_delta) -> Result<全文>`，边收边回调增量，结束返回全文；取消就是丢弃 future（连接随之关闭）。不引入 futures / Stream 抽象，回调对 Tauri 事件转发已经够用。用 `Response::chunk()` 逐块读，不需要 reqwest 的 stream 特性。
- **M5.2 超时**：两段——从发出请求到第一段文字的「首字超时」（备用链的超时就设它，需求默认 8 秒，适配器自身默认 30 秒），以及开始输出后两段之间的「间隔超时」（默认 30 秒）；连接超时 10 秒。超时前已经收到的文字照常交出，由调用方决定怎么显示。
- **M5.2 输出口径**：只把正文算作输出——DeepSeek 的 `reasoning_content`、Claude 的 thinking、Gemini 带 `thought: true` 的片段都不交给界面；结果去掉空白后为空就返回「空结果」错误，方便备用链切换。内容过滤 / 拒答（OpenAI `content_filter`、Claude `refusal`、Gemini `blockReason` 或 SAFETY 等结束原因）统一为「内容被模型拒绝」。
- **M5.2 请求细节**：OpenAI 兼容接口只有一段文字时 content 用字符串（兼容只认字符串的老服务和部分本地服务），有图片才用数组；Gemini 模型名去掉 `models/` 前缀；Claude 固定 `anthropic-version: 2023-06-01`。
- **M5.3 只用官方接口**：DeepL、Google Cloud Translation、Azure Translator 都要用户自己的 Key，不用网页版的免费非公开接口（随时可能失效，也不符合服务条款）。三家固定列在「模型服务」页左侧的「机器翻译」分组里，不需要添加 / 移除，填了 Key 就算可用；Key 存系统凭据库，账户名 `mt-deepl` / `mt-google` / `mt-microsoft`，和大模型服务商的 id 不会撞名。配置里只放非敏感的 `mt.microsoftRegion`。
- **M5.3 语言代码**：内部统一用 BCP 47 风格（`zh-Hans`、`zh-Hant`、`en`、`ja`……），在适配器里换成各家写法（DeepL 目标 `ZH-HANS` / `EN-US`、原文不分变体；Google `zh-CN` / `zh-TW`；微软原样），检测到的原文语言也换回统一写法，留给 M6.3「原文已是目标语言就翻成第二语言」使用。
- **M5.3 分段**：文本按行拆成数组发送、按原位置拼回，空行不发但留位——三家都保证译文与原文一一对应，行数和段落结构不会被服务改乱；每批最多 50 段（DeepL 的上限）。
- **M5.4 链的结构**：每项是带 `type` 标签的引用（`{type:"llm",provider,model}`、`{type:"mt",kind}`、`localOcr`、`degrade`），不复制地址和 Key，执行前用 `resolve` 现取；默认识别链是「本地 OCR」，翻译和一步到位链为空（没有服务商就没有可用后端，设置页给出下一步提示），不在勾选模型时自动加入链——链的顺序是用户的明确选择。
- **M5.4 切换规则**：失败、超时、空结果、缺 Key、被拒都换下一个（另一个模型可能能答）；超时只管「首字」（机器翻译是整个请求），开始输出后不再按备用链超时打断。切换时发出 `Failed` 事件，界面据此清掉上一个后端的半截输出再显示新的。关掉「自动切换」只用第 1 项。超时可选 5 / 8 / 15 / 30 秒，实际限制在 3–60 秒。
- **M5.4 失效项**：服务商被移除时，链里引用它的项一并去掉；模型只是取消勾选（或识别 / 一步到位链里的模型不再带「视觉」标签）时保留并划线标「已失效」，执行时跳过，重新勾选即恢复——取消勾选常常是临时的。缺 Key 的项保留，执行时报「没有 Key」并切换，结果卡片能说清原因。
- **M5.5 提示词存储**：配置里只存用户改过的内容，空字符串表示用默认值（编辑到和默认一模一样也存空）。这样以后改进了默认提示词，没改过的用户自动用上；「恢复默认」就是清空。默认提示词只在 Rust 里有一份，设置页通过 `prompt_defaults` 取。
- **M5.5 变量规则**：只认四个变量，其他花括号（如一步到位提示词里的 JSON 示例）原样保留；语言变量渲染成语言名（「简体中文」）而不是代码，模型更不容易误解；变量为空时整行删除，免得留下「以下术语保持原样：」这样的半句；翻译时原文一定会送到模型（提示词里没有 `{text}` 就接在最后）。整段提示词作为一条用户消息发送，不拆 system——一步到位要附图片，放在同一条消息里最稳。
- **M6.1 任务模型**：每次识别 / 翻译是一个带 id 的后台任务，事件 `task:event`（stage / src / src-reset / dst / dst-reset / done / error）只发给发起的窗口；同一 id 再次发起、关闭卡片、结束截图都会中止旧任务（丢弃 future，连接随之断开），不会有迟到的结果写进新卡片。前端用纯函数 `reduce` 把事件折叠成卡片状态（有单元测试）。
- **M6.1 识别**：识别用选区原图，不带标注（马赛克、箭头会干扰识别），最长边缩到 2048 像素再发（更大只多花 token）；识别链里的「本地 OCR」在 M4 完成前报「本地 OCR 还没有安装」并切到下一项，所以只配了视觉模型也能用。识别链为空、翻译链为空时卡片里直接告诉用户去设置哪一条链。
- **M6.1 卡片交互**：原文在识别时只读、之后可编辑；译文流式输出时只读并自动滚到底，完成后可编辑；复制译文、贴图在完成前不可点。在卡片文本框里打字时，截图快捷键（数字键选工具、空格、Ctrl+C 等）全部让给文本框，只有 Esc 仍然关闭卡片。卡片打开时隐藏放大镜（会挡住卡片）。卡片位置避开选区和工具条的外接矩形（工具条可能比选区宽）。
- **M6.1 目标语言**：先加 `translation.targetLang`（默认简体中文）和设置页的下拉框；第二语言、双语对照、不翻译列表在 M6.3 补充。
- **建窗口的命令必须是 async**：Tauri 的同步命令跑在主线程，在里面创建 WebView 窗口会卡死整个程序（真机测试「贴图」时发现）。`capture_pin_text` 和已有的 `capture_pin` 一样改为 async。
- **M6.3 语言检测**：不引入语言检测库，按文字系统判断：假名 → 日语、谚文 → 韩语、汉字为主 → 中文（简繁算同一种）、西里尔 → 俄语、阿拉伯、泰文；拉丁字母只在英语常见虚词占比够高时判为英语，法德西等分不清就返回「不确定」，照常翻译——误判成「已是目标语言」比多翻一次糟糕得多。判断在翻译前做，大模型和机器翻译走同一套规则。
- **M6.3 开关的实现**：保留格式、自动判断专业术语关掉时，删掉提示词里含标记文字（「保持原有的段落」「自动判断专业术语」）的整行；用户自己写的提示词没有这些行就不受影响。为此把一步到位默认提示词里「术语判断」和「不翻译列表」拆成两行，关掉术语判断不会连带删掉不翻译列表。三个开关和不翻译列表只影响大模型，机器翻译照原文翻（设置页说明里写明）。
- **M6.3 一步到位**：输出是 JSON，半截不能给人看，所以一步到位阶段不流式显示，收完整再解析（取第一个 `{` 到最后一个 `}`，也认 original / translated 等常见键名）；解析失败算这个后端失败，换下一个。链里走到「降级」或根本没有可用视觉模型时，改走识别链 → 翻译链，说明里写「一步到位已降级 →」。
- **M6.3 双语对照**：卡片本来就同时显示原文和译文，所以双语对照作用在交出去的结果上：复制和贴图时原文、译文按段落（空行分隔）交替排列，段落数对不上就原文在前、译文在后。默认开启（与原型一致）。
- **M6.4 一张卡片一条记录**：翻译历史按卡片记——第一次完成时新增，在同一张卡片里改原文重新翻译时更新这一条（最近时间更新、排到最前），避免改几个字就多出几条近似记录；关闭卡片后再翻译同一段文字算新的一条。重新翻译后「后端」只记这次翻译用的后端。原文已是目标语言、按设置没有翻译的不记（没有译文）。
- **M6.4 不存图片**：翻译历史只存文字（占用小，可全文搜索）；截图本身如果贴出来会进贴图历史。占用空间按文字的 UTF-8 字节数统计，供 M10.3 按空间清理。
- **M4.1 模型来源与分发**：用 PaddlePaddle 官方的 ONNX 仓库（PP-OCRv5_mobile_det_onnx / rec_onnx），地址固定到提交哈希，每个文件校验 SHA-256，模型不入库。按编程计划「安装包 ≤ 25 MB（不含模型），模型首次运行时下载」，应用里的首次下载放在 M4.4 接入时做（复用同一份地址和哈希）。
- **M4.1 ONNX Runtime 的链接方式**：pyke 提供的 Windows 版是静态库（编进程序，不需要 onnxruntime.dll，命令行程序 23 MB），但总是带着 DirectML，会让程序启动时依赖 DirectML.dll / D3D12.dll / DXCORE.dll。我们只用 CPU，所以在 build.rs 里把这三个 DLL 设为延迟加载（`/DELAYLOAD` + delayimp.lib），不用 copy-dylibs，也不随程序发布 18.5 MB 的 DirectML.dll。应用接入时（M4.4）src-tauri 的 build.rs 要做同样的设置。TLS 用 rustls（Linux 版不依赖 OpenSSL）。
- **M4.1 检测参数**：屏幕截图里文字几乎都是水平的，文字框用轴对齐矩形，不做旋转矫正。送进检测模型的长边上限实测选 1440：12 px 和 15 px 的测试页在 1920 / 1440 都是零错误，1440 检测耗时减半（约 460 ms → 215 ms）；1280 开始出现个别错字，960 漏字。小图不放大。阈值沿用 PP-OCRv5 的 inference.yml（0.3 / 0.6 / 1.5）。
- **M4.1 识别并行**：一次推理一行比按批推理快得多（批内要按最宽的行填充，长行把整批拖慢）；ort 的会话一次只能跑一个推理，所以开 2 个识别会话、各 5 线程并行（12 核上实测最快，3–6 个会话反而互相争抢）。短行按 PaddleOCR 的做法至少填充到 320 宽。环境变量 SNAPMIND_OCR_REC_SESSIONS / SNAPMIND_OCR_REC_THREADS 留着调参。
- **M4.1 性能未达标与后续方向**：瓶颈是识别——屏幕文字行高 15–25 px，要放大到 48 px 送进模型，一行 500 px 宽的文字变成约 1200 px 宽的输入，单行单线程约 65 ms。后续可试：DirectML（GPU）执行（静态库已带，Windows 10 以上系统自带 DirectML）、int8 量化的识别模型、只识别用户划选的部分、检测按文字大小自适应缩放。M4.2 的评测命令行会把速度一起记录，每次优化都对比。
- **版本号回到早先的里程碑时**：版本号必须单调增加，所以 M4 的任务（用户同意下载后才回头做）继续在当前最高版本上升 patch（0.7.3 → 0.7.4），不退回 0.5.x。
- **M4.2 样本集怎么来**：编程计划设想用 30–50 张真实截图，但真实截图要人工逐行标注真值，且可能含个人信息、不便入库。改为写 HTML 页面、用本机 Edge 无头截图：渲染是真实的浏览器排版（ClearType、各种字体和配色），每一行都用 `<br>` 显式断开并禁止自动换行，所以真值的行和段落是精确的，样本可以随时重新生成。之后遇到真实截图里认错的情况，再照着做成新的样本页加进来。
- **M4.2 指标定义**：比较前去掉所有空白（模型会省略中英文之间的空格，这由 M4.3 的拼接负责），省略号统一成「...」。行先一对一贪心配对再算错字，阅读顺序（双栏、按钮在标签右边）不影响字符错误率；多识别出来的行算插入错误。行召回率按「配上且错误率 ≤ 10%」计；段落 F1 同样按段落文字错误率 ≤ 10% 算命中。合计按字数 / 行数加总（微平均），不对样本求平均。
- **M4.2 当前的错误**：「•」认成「·」、省略号「…」认成「..」、12–12.5 px 的衬线字体有个别错字（crisp → crip、left → let）、12 px 灰色小字「yyyy」少一个 y、片假名「ッ」认成「ツ」。都是识别模型层面的问题，记下来作为以后换模型或做后处理的对照。
- **测试脚本编码**：PowerShell 5 把无 BOM 的 UTF-8 脚本当 ANSI 读，脚本里写的中文测试文字会先变成乱码；需要中文时从 UTF-8 文件用 `Get-Content -Encoding UTF8` 读。
- **M4.3 不用版面模型**：需求 12.1 允许「嫌模型太重就按行框投影分栏」。屏幕截图的栏、按钮、气泡之间都有明确的空白，「只和正上方、横向重叠的行比较」已经把它们隔开，不需要 PP-Structure（约 10 MB、每次多 100 ms 以上）。表格、公式的识别在 M8 单独做。
- **M4.3 字号怎么量**：DB 检测框按面积 / 周长外扩，高度随行长和字号变化，11 px 的菜单字和 17 px 的正文框高几乎一样，不能用。改为在原图上量笔画：框四边像素的中位数当背景，和背景的差超过「这一行最浓笔画 × 0.4」算笔画，取笔画最多的那段连续行（挤进框里的相邻行被排除）。英文没有下伸字母（g j p q y）时笔画只有字号的约 3/4，所以字号 = 笔画高度 ÷ 按这一行的字母估出的比例（中日韩 / 括号 / 上下都有 0.95、只有上伸 0.75、只有下伸 0.72、都没有 0.5）。
- **M4.3 阈值与需求的差别**：需求写的是「行间距 ≤ 0.6 倍行高」，实测正文 1.5–2.0 倍行距时笔画间空隙是字号的 0.55–1.09 倍，按 0.6 会把常见的网页正文拆碎；改用「空隙 ≤ 1.2 倍字号」（约等于 2.15 倍行距），样本里最松的正文 1.09、最紧的菜单 1.29。字号之比 ≤ 1.25、文字颜色差 ≤ 48、背景色差 ≤ 24、左对齐容差 0.6 个字、首行缩进最多 4 个字；和这段上一对行比，空隙变大超过 1.35 倍 + 0.3 个字算行距突变。「上一行接近栏宽或末尾没有终止标点」这一条没用：截图里常有句号结尾的短行仍在同一段（聊天气泡、说明文字），而菜单项都没有标点，这条两头都会判错。
- **M4.3 代码块**：行尾是 `{ } ;`、以 `//` `/*` `#!` 开头、或者括号和运算符占六分之一以上（不含中日韩文字）算代码行；连续两行都是代码行时不看缩进、只看空隙（≤ 1.2 个字），拼接时保留换行，缩进按这段文字的中位字宽换算成空格。
- **M4.3 样本生成可以只生成指定的**：`node scripts/make-ocr-samples.mjs <名字…>`，避免 Edge 更新后重新渲染旧样本、让历史评测结果失去可比性。
- **M4.4 模型首次使用时下载，不自动下**：下载第三方文件要用户知情，所以卡片里明确写出大小和来源，点了才下；下载在 Rust 后台进行，关掉卡片也会下完，进度通过 `ocr:download` 广播给所有窗口。地址和哈希与 `scripts/fetch-models.mjs` 同一份（`snapmind_ocr::models`）。环境变量 `SNAPMIND_MODELS` 可以换目录；调试版在下载目录没有模型时用仓库里的。
- **M4.4 引擎按需加载、加载后常驻**：开机就加载要多占约 100 MB 内存，第一次识别多等 0.4 s 可以接受；之后常驻，避免每次都重新加载。
- **M4.4 识别结果留在 Rust**：右键划选只把行号传回去，由 `layout::compose` 对选中的行重新跑段落规则再拼接（需求 12.1 第 6 条），前端不复制一份拼接逻辑。每张卡片一份，最多留 4 份，关卡片时释放。
- **M4.4 交互细节**：卡片打开时右键不再取消选区（右键拖动 = 划选、右键单击 = 恢复全部），`Esc` 先关卡片；选区被移动或调整后检测框不再画（对不上了），卡片保留。没选中的行用截图遮罩同样的颜色盖住，和「选区外变暗」是同一个意思。换排列方式或划选会用重新拼接的文字替换掉卡片里的修改。文本框不自动获得焦点，这样 Ctrl+C / Enter 仍是「复制文字并结束」。段落之间空一行（和视觉模型识别的输出、翻译的双语对照一致）。
- **M4.4 图标噪声过滤**：界面截图里工具栏图标会被检测成「一行」，识别成一两个低置信度的怪字或「□」。引擎去掉首尾的 □，丢掉置信度 < 0.5 的行和只有一两个字且置信度 < 0.8 的行；样本集评测结果不变，真机浏览器工具栏区域 28 行 → 13 行，真文字都保留。
- **M4.4 发布构建里 OCR 按速度优化**：全局 release 是 `opt-level = "s"`，`snapmind-ocr` 单独设为 3（预处理和笔画测量是逐像素循环）。
- **M4.5 透明文字层怎么对齐**：用笔画范围（不用外扩过的检测框）定位每一行，字号 = 笔画高度，横向拉伸比例在 100px 字号下量一次（缩放时字号跟着变，比例不变），上下各多出 20% 字高做选区底色。文字透明、只显示选区底色，看起来像直接在图上选字。
- **M4.5 复制用 Rust 拼接**：浏览器把分开摆放的各行选中文字直接连在一起（「them,then」），所以页面只收集「行号 + 选中的那部分」，由 Rust 替换掉这些行的文字后用 `layout::compose` 按段落规则拼接再写剪贴板，和识别卡片一套规则。
- **M4.5 双击的取舍**：需求里双击关闭贴图，而在文字上双击习惯是选词。改为文字上双击选词、空白处双击关闭；Esc 有选中文字时先取消选择，再按一次才关闭。
- **M4.5 不自动下载模型**：贴图是后台识别，没有地方征求同意，所以没下载模型时直接跳过；在识别卡片里下载过之后，新贴出的贴图都会自动识别。
- **M6.2 没有版面模型时的「公式和表格不覆盖」**：按文字判断——连续的代码行、没有任何字母或汉字的块（价格、时间、编号）、运算符占四分之一以上且字母不到一半的块（公式）保持原样；表格的单元格本来就各自成段，翻译后原位替换，不单独识别表格。M8 有了表格 / 公式识别后再换成按版面类型判断。
- **M6.2 一次翻译再拆回**：逐段请求在界面截图里（几十个短标签）又慢又贵，所以先整段一次翻译、按空行拆回；机器翻译接口保证段落一一对应，大模型偶尔合并段落时才逐段重译。
- **M6.2 导出复用标注层**：覆盖层渲染成标注层的底层（`renderLayer` 加了 `under` 参数），复制、贴图、保存都不用改 Rust 的导出路径；选区动过以后覆盖不再画、也不导出（位置对不上）。
- **M6.2 范围**：原位覆盖做在截图翻译里。贴图工具条的「翻译（原位覆盖）」按钮要先补贴图工具条上的识别 / 翻译入口，留到贴图功能补齐时一起做（覆盖块的生成和绘制代码可以直接复用）。
- **M7.1 剪贴板还原只放回原格式**：系统会在文字（CF_UNICODETEXT / CF_TEXT / CF_OEMTEXT）和位图（CF_BITMAP / CF_DIB / CF_DIBV5）之间自动合成，枚举时原程序放的排在前面。连合成的一起放回去，读的程序可能拿到转换过的那份（实测 .NET 放的位图会错位三个像素），所以每族只放回原来那个；原来是存不下的 GDI 位图时放回系统合成的 CF_DIB，让系统再合成其余的。
- **M7.1 不在 UI Automation 说「没选中」时模拟复制**：VS Code 等程序没有选区时 Ctrl+C 会复制整行，模拟复制会误取。只有控件根本不支持 TextPattern（Chromium / Electron 默认）才退回模拟复制。环境变量 `SNAPMIND_SELECTION=copy` 可以强制走模拟复制（调试用）。
- **M7.1 版本号**：进入 M7，按里程碑规则从 0.8.1 开始（仍然大于之前的 0.7.9）。
- **M7.2 用焦点判断「点别处」**：卡片弹出时拿到焦点（快捷键刚按下，系统允许前台切换），失去焦点就收起；不装全局鼠标钩子。代价是弹出时会抢走原程序的焦点，划词翻译的场景下可以接受（固定后可以编辑本来也需要焦点）。
- **M7.2 卡片窗口池**：一张空闲卡片常驻（隐藏），弹出只是挪位置；钉住的卡片离开池子，同时后台预建下一张。多出来的卡片收起时直接销毁，只保留一张空闲的。
- **M7.2 事件只发给本窗口**：同时有几张卡片时，全局监听会收到发给别的卡片的通知（实测钉住的卡片被新卡片的通知重置）。卡片页面改用 `getCurrentWebviewWindow().listen`；要翻译的文字存在 Rust 里由页面来取（只取一次），新建窗口页面加载前错过的通知靠加载完主动取补上；任务 id 带窗口名，几张卡片同时翻译时互不取消。
- **M8.1 Markdown 走识别链**：没有单独的「Markdown 链」——识别链里的视觉模型换成 Markdown 提示词，本地 OCR 换成按版面转换，备用切换规则和识别一致，设置项不增加。
- **M8.1 预览的安全处理**：预览渲染在能调用 Rust 命令的遮罩页面里，内容来自大模型，按不可信处理：只放行 <sup> <sub> <br> <mark> <kbd>（提示词要求上下标用 HTML），其余 HTML 原样转义；链接只显示、不可点（不生成 href，地址放在悬停提示里）；图片显示为「［图片：替代文字］」，不去取远程图片。引入 marked（MIT，固定 15.0.12）而不是自己写 Markdown 解析器——表格、列表嵌套、代码块这些细节自己写很容易出错。
- **M8.1 公式**：$…$ / $$…$$ 先按源码高亮显示，M8.3 接入 KaTeX 后再渲染（已接入：写错的按源码标红，悬停看原因）。
- **M8.1 版本号**：进入 M8，从 0.9.1 开始。
- **测试经验：系统另存为对话框**：用 SendKeys 往文件名框里打路径会被中文输入法转换成汉字（实测文件名变成「落实三、…」），改为把路径放进剪贴板后 Alt+N、Ctrl+A、Ctrl+V、回车；对话框出现可能要 2 秒以上。
- **M8.2 SLANet 的三个坑**：① 模型是在裁好的表格上训练的，选区四周的大片空白会被当成空行空列——推理前先按背景色裁掉空白；② 单元格框按补零后的正方形归一化（横竖都乘长边），不是按原图宽高；③ 常漏掉合并单元格——一行字横跨到相邻的空单元格（盖住它三成以上）就合并成一格（文字可能分到左格也可能分到右格，两个方向都处理）。表头靠模型的 <thead>，模型没给就不标。
- **M8.2 模型文件**：table.onnx 和识别模型放在同一个目录（`配置目录/models/ppocrv5`），结构标记表写在代码里（和固定的模型版本一一对应），不下载 yml。下载命令加 `table` 参数，已下载、校验通过的文件跳过。ONNX Runtime 一个进程只允许一个环境，识别和表格模型改为共用一个。
- **M8.2 视觉模型的提示词不进设置**：输出要能被程序解析成表格，所以用固定提示词（只输出 <table>，表头放 <thead>，合并用 colspan / rowspan）；设置里的四套提示词不变。
- **M12 暂停而不是盲写**：Linux 平台层（portal 截图 / 录屏 / 全局快捷键、layer-shell 遮罩和贴图、主选区取词）离开真实的 KDE Wayland 环境既编译不了（需要 webkit2gtk、ashpd 等系统库），也验证不了交互；照着文档写一大片没编译过的代码只会留下半成品（编程计划：宁可少做一个任务，也不要留下半成品）。等有 Linux 机器再做。
- **F9 检测框选择（取代 F6 / M4.4 的规则）**：默认全选，选中状态只有一份行号列表，没有「没挑过」这个特殊状态；单击始终是切换；没有右键划选和右键恢复，识别卡片打开时右键不做任何事（不取消选区，免得误丢结果）。
- **F7 本地识别模型能不能商用**：能。PP-OCRv5 mobile 检测 / 识别和 SLANet_plus 表格模型都是 PaddlePaddle 官方以 Apache-2.0 发布的（Hugging Face 和魔搭的模型卡都标 apache-2.0，PaddleOCR 仓库也是 Apache-2.0），允许商用、修改、分发，没有「仅限非商业」之类的附加条款，也不收费。义务只有：分发模型或改过的模型时附上 Apache-2.0 许可原文和原有的版权 / NOTICE 声明、改动要注明、不能用 PaddlePaddle / 百度的商标给产品背书。SnapMind 的安装包不带模型（用户第一次用时从官方仓库下载原文件），所以连分发义务都很轻；关于页写明了来源和许可。程序里静态链接的 ONNX Runtime 是 MIT（要保留版权声明），界面用的 Tauri、Svelte、KaTeX 是 MIT / Apache-2.0，F3 打包的 models.dev 数据是 MIT。正式商用发布前建议生成一份完整的第三方许可清单（cargo-about + 前端依赖）随安装包附上。
- **F5 「复制」放两种格式**：Excel 粘贴时优先用剪贴板里的 HTML（保留合并单元格、表头加粗），记事本、聊天框只认纯文本，就用同时放进去的制表符文本——一个按钮在哪儿粘贴都对。「复制纯文本」给只要文字的场合（不想带格式进 Word、或要 Markdown / CSV 源码）。
- **F5 预览 / 编辑记一个设置就够**：不另做「默认格式」设置——视图只有表格最常用，Markdown / CSV 是临时看源码用的；只记「预览还是编辑」，卡片上切换和设置页是同一个值。预览是默认：识别完多半是直接复制，误点单元格不会改到内容。
- **F4 拖动不等于固定**：没固定的卡片拖完仍然是「点别处就收起」——拖动只是挪开挡住的内容，要留着就点图钉，两件事分开最好预期。固定的卡片只保留一张「当前」的（最近钉住的那张）：再划词都进它里面，所以不会越钉越多；想对照两段译文时，先取消固定再钉新的。
- **F4 接着翻译是替换不是追加**：新取到的文字替换原文、重新翻译；追加会让卡片越来越长，而且原文和译文对不上段落。
- **F3 能不能看图听谁的**：模型名永远追不上新模型（实测 2026 年 11 月 OpenRouter 上 GPT-6、Kimi K3、Qwen3.8、GLM-5.3、Gemma 4 这些名字规则一个都不认识），所以按可信程度排：服务商在列表里自己说的 > models.dev 目录 > 名字规则。目录和名字规则是「或」的关系：目录里有的托管方只开放文字输入（例如部分 Gemma 3 量化版被标成纯文本），厂商文档写明能看图的系列也算能看图。用户在设置里改过的标签始终优先（合并模型列表时保留）。
- **F3 目录随程序打包、不联网拉**：models.dev 的完整 api.json 有 6.9 MB，每次获取模型列表都下载太重，中国大陆访问也不稳；只取「模型名 → 看图 / 推理」两个标记压成 56 KB 的 TSV 编进程序，发版前跑 `node scripts/vision-index.mjs` 刷新，靠自动更新带给用户。服务商自己带模态信息的（OpenRouter 等）本来就是实时的。
- **F3 参考 Magpie 什么**：Magpie（yetone/magpie，MIT）只参考了它的服务商清单、各家的官方接口地址，以及「用 models.dev 当模型目录」这个思路；代码全部自己写。Magpie 里偏编程套餐（Coding Plan / Token Plan）、海外云厂商托管（Bedrock、Vertex、Azure）和小众中转站没有加，需要的用「自定义服务」接。
- **F3 新服务商都走 OpenAI 兼容接口**：它们的官方文档都提供 OpenAI 兼容地址，接口格式、流式、图片输入写法和现有实现一致，所以只是目录里多一行，不加新代码路径。
- **F2 两种都支持，而不是只装 Program Files**：只做「为所有用户安装」会让没有管理员权限的账号（公司电脑、学校机房）装不了，所以用 NSIS 的 MultiUser：有管理员权限的账号默认装 Program Files（和大多数软件一致），没有的照样能装到自己目录。自动更新沿用原来的安装方式，装在 Program Files 的版本更新时会弹一次 UAC。用户数据（配置、模型、历史、日志）始终在 `%APPDATA%\SnapMind`，程序目录里不写任何东西，所以两种位置行为一致。
- **F1 怎么判断地区**：不联网测 IP（多一次请求、还涉及隐私），读系统设置里的「国家或地区」——它决定的只是先试哪个源，判错了也会自动换源，代价只是多等十几秒。港澳台有自己的 GEOID，不算在内。环境变量 `SNAPMIND_REGION=cn / other` 可以强制指定（测试用，也给特殊网络的用户留个口子）。
- **F1 为什么选魔搭而不是 hf-mirror**：hf-mirror 是个人维护的反代，境外访问时还会直接跳回 huggingface.co；魔搭是阿里云的官方模型平台，PaddlePaddle 官方账号自己上传的同一份 ONNX，文件哈希和 Hugging Face 逐字节一致，地址固定到提交，不会悄悄变。不做下载源设置项：自动排序 + 失败换源已经覆盖了需要它的情况。
- **M11.3 先校验、再动贴图**：插件的 download_and_install 在「下载完」回调之后才校验签名，如果在那个回调里关贴图，一个被篡改的更新包会先把用户的贴图关掉再失败。改为 download（返回前已校验）→ 写贴图进历史 → install。
- **M11.3 用户点了才安装**：后台只检查不下载（不偷跑流量、不在用户忙的时候退出程序）；提示放在托盘菜单和「关于」页，不弹窗打断。
- **M11.3 没有公钥就当没配置**：签名密钥属于用户的密钥，不由我代为生成；公钥为空时客户端不检查、「关于」页说明去发布页下载，构建和其他功能不受影响。用户生成密钥、填入公钥后，同一套代码直接生效。
- **M11.3 发布渠道**：更新源指向本仓库的 Releases，但仓库是私有的，已安装的 SnapMind 匿名访问拿不到 latest.json。要么把仓库改为公开，要么另建一个公开仓库专门放安装包（需要改 endpoints 和 RELEASE_REPO）。AGENTS.md 规定不自行创建新的同步目标、只推送到私有仓库，所以留给用户决定；`pnpm publish-release` 在仓库私有时默认拒绝。
- **M11.2 日志放哪、记什么**：放在配置目录的 `logs` 下（和配置、历史在一起，用户好找，「关于」页一键打开）。不引入 log / tracing 等日志框架：只需要「写一行到文件」，两个宏加一个 30 行的滚动写入器就够了。只记操作失败、启动和耗时（按键到遮罩出现、OCR 耗时等，便于事后查性能），不记截图内容、识别出的文字和翻译内容，划词只记字数。1 MB × 3 个文件，单条记录不截断。
- **M11.2 崩溃恢复恢复什么**：崩溃时真正会丢的是「开着的贴图」（截图编辑态几秒钟就结束，设置已经即时写盘，历史在关闭时入库）。所以只给贴图留底：贴出时写一份到磁盘（后台快速 PNG 压缩，不拖慢贴出），位置变化时重写几十字节的描述。不另设「正在运行」标记文件：正常关闭和托盘退出都会删掉，启动时目录里还有东西本身就说明上次没正常退出（崩溃、被结束进程、关机时没来得及退出都算，关机后开机也能找回贴图）。恢复时标注已经合进图片（不能再单独改），文字卡片按原文重新排版。不做崩溃后自动重启：需要另起守护进程，不值得。
- **M11.2 托盘退出时贴图写进历史**：「关闭即入库」以前只对单张关闭生效，托盘退出直接结束进程，开着的贴图就丢了。现在退出前同步写完历史再退出（几张贴图不到一秒）。
- **M11.2 首次运行的判断**：用配置文件「是否刚刚新建」判断，不另加「已看过引导」的配置项；老用户升级不会弹引导，想看可以从「关于」打开。引导是设置窗口里的一页（不在导航里），左边导航照常可用，不另开窗口。
- **M11.1 减弱动效的做法**：设计规范说「选减弱动效时只保留淡入淡出」。不为每个动画写两套，而是给位移和缩放乘一个变量 `--m`（完整 1、减弱 0）：同一个关键帧在减弱时只剩透明度变化；再在减弱时把所有过渡限制在颜色、透明度上（悬停放大、滑块移动、尺寸变化直接到位）。JS 过渡（popIn / popOut、flip、slide）在 `$lib/motion` 里统一判断。系统关掉「显示动画」（prefers-reduced-motion）时也按减弱处理，不必再单独设置。加载中的转圈保留（它是状态指示，不是装饰性动效）。
- **M11.1 设置窗口按需创建**：设置很少打开，原来常驻一个隐藏的设置页（一个页面进程约 25–40 MB，还占 GPU 内存），改成点开时才建、关掉就销毁，打开时慢几百毫秒；截图遮罩、划词卡片、贴图工具条这些要求秒出的仍然预热。从工具条「自定义工具条…」等入口新建时，用初始化脚本告诉页面打开哪一页（窗口已开着时仍然发事件）。
- **M11.1 常驻内存的预算达不到**：编程计划第 6 节写的 ≤ 120 MB 是按「一个进程」估的。WebView2 每个窗口一个页面进程，再加共用的浏览器进程和 GPU 进程：空闲时浏览器进程约 50 MB、GPU 进程 110 MB 以上，光这两个就超过预算，SnapMind 自己的进程只有 10 MB。试过 `--renderer-process-limit=1` 让页面共用进程，WebView2 不理会（每个 WebView 一定独立）。能做的已经做了（设置窗口不常驻，空闲合计从 363 MB 降到 276 MB；SnapMind 进程 + 页面进程 90 MB，在预算内）。截图后 GPU 进程缓存整屏纹理涨到约 300 MB，可以试 WebView2 的 MemoryUsageTargetLevel（遮罩停放时设为 Low），但会不会拖慢下一次出现要实测，先记下。
- **M10.5 悬浮球的交互**：单击就是最常用的截图，其他放进右键菜单（系统原生菜单，带当前快捷键）；拖动交给系统窗口拖动（按下后移动超过 3 像素才开始，免得点击被当成拖动），比在页面里自己算位置跟手；松手后贴最近的左 / 右边（上下不贴，屏幕上下边常是任务栏和标签页），一半藏在屏幕外，指针移上去才完整露出，不挡内容。位置存窗口中心点，下次按它重新找显示器贴靠，换了显示器也不会跑到屏幕外；多显示器横排时藏起的那一半会伸到相邻屏幕上（少见，以后再看）。
- **M10.5 不出现在截图里**：悬浮球是置顶窗口，截图会抓到它，所以一直设为截屏排除（和长截图 / 录屏时的遮罩同一个办法）；副作用是别的录屏软件、远程会议共享屏幕时也看不到它，对快捷入口来说正好。
- **M10.4 加密方式**：Key 用 PBKDF2-HMAC-SHA256（60 万次，OWASP 的建议值）从密码派生 256 位密钥，AES-256-GCM 加密（自带完整性校验，密码不对必然解不开而不会解出乱码），盐 16 字节、随机数 12 字节，每次导出都重新随机。导出时密码至少 6 位、输两次；忘了密码只能重新填 Key。没有加密时 Key 一律不进文件。
- **M10.4 导入的语义**：选中的每一类整块替换（例如「模型服务与备用链」会把服务商列表换成文件里的），文件里没有的字段（旧版本导出的文件缺新设置）保留当前值；先校验整份补丁合法、密码能解开，再备份、再写，任何一步失败都不改动。导入的 Key 写回系统凭据库（同名的覆盖）。
- **M10.4 自动备份的时机**：需求要「修改重要设置前、导入前和每周」。重要设置定为服务商、机器翻译、备用链、快捷键、提示词、工具栏（改坏了最麻烦的几项），最多每小时一份，免得拖动一次工具条就多一份；导入、恢复备份、恢复默认前无论开关都会备份；每周一份在启动时和每次修改配置时检查。开关只控制前两种。保留最近 20 份。
- **M10.4 恢复默认保留什么**：需求说「模型服务和历史记录保留」——服务商、机器翻译设置和备用链都算模型服务；历史记录在数据库里本来不受影响，历史的保留方式也保留（变回默认的 1024 MB 可能马上清掉用户的历史）。
- **M10.3 保留方式的口径**：按条数是贴图和翻译各算各的；按空间是两类合计，贴图按原图 PNG + 缩略图的实际字节，翻译按原文、译文、后端说明的 UTF-8 字节估算（和统计显示的口径一致）。按空间超出时先删最早的贴图（图片占大头，需求说「优先清理贴图图片」），整条删除而不是只删图片——只剩文字的贴图记录既不能重新贴出也看不到缩略图，留着没有用。清理在写入历史后和改保留方式后做，不另开定时任务。
- **M10.3 重新贴出 = 从历史里取回**：重新贴出后把这条从历史里删掉，贴图关掉时会重新记进来（时间更新为这次关闭的时间），历史里始终只有一份。文字卡片按原文重新排版贴出（跟随当前主题），截图贴图用原图；贴在鼠标所在屏幕中央，比屏幕 90% 还大时缩小显示。
- **M10.3 缩略图走自定义协议**：没有开放 Tauri 的 asset 协议（那会让页面能读任意本地文件），而是加了只认 `/<id>` 的 `snapthumb` 协议，只能读历史目录里对应的缩略图。
- **M10.3 清空要点两次**：清空是不能撤销的删除，按钮第一次点变成「再点一次清空」，移开焦点就复原，不弹对话框。
- **M10.2 固定的按钮**：截图工具条的退出、复制（最右边的主按钮），贴图工具条的关闭和「更多」里的不透明度滑块不能排、不能藏——它们是收尾的出口和连续调节的控件，藏掉会让人困在截图里或者调不了；「更多」按钮本身也一直在（里面至少有「自定义工具条…」）。隐藏的标注工具仍可以用数字键 1–7 选中。
- **M10.2 布局的存法**：只存顺序和隐藏两个列表，`more` 当作分隔线放在顺序里，和设置页一行一行的样子一一对应；解析时容错（不认识的、重复的去掉，缺的补上），所以以后加新按钮不用迁移配置。分组分隔线不存，按「标注 / 动作」自动加。
- **M10.2 拖动排序自己写**：没用 HTML5 拖放（拖的是半透明截图、松手前看不到其他行让位），改成按住把手后指针移动超过半行就和邻居换位，拖着的那行跟着指针走、其他行用 flip 动画让开，松手才保存。上移 / 下移按钮给不方便拖的情况用。
- **M10.2 「自定义工具条…」**：只打开设置并跳到工具栏页，不结束截图（截图里可能有还没交出去的内容）；设置窗口会在遮罩后面，退出截图后就能看到。
- **M10.1 各页先放已经能用的功能**：原型里还没实现的项不放假开关——识别选项里的「Markdown 方言」（只实现了 Obsidian）、「表格默认格式」、「识别段落和行」（识别卡片上有逐行 / 段落切换）、外观里的悬浮球（M10.5）和减弱动效（M11.1）、关于里的检查更新（M11.3）、贴图的「贴出后自动识别」都等对应功能做了再加。工具栏、历史记录、配置文件三页先放只读或基础内容，排序隐藏（M10.2）、保留方式 / 统计 / 缩略图 / 重新贴出 / 清空（M10.3）、导出导入备份（M10.4）随各自任务补上。「识别槽 / 翻译槽」两排卡片和备用链重复（链的第 1 个就是槽里选的），用流程卡片代替。
- **M10.1 快捷键录制规则**：存 Tauri 写法（`Ctrl+Shift+O`），显示成 `Ctrl + Shift + O`（Super 显示为 Win）。主键必须配 Ctrl / Alt / Shift / Win，F1–F24、PrintScreen、Pause 可以单独用（免得占掉普通打字的键）；Esc 取消、Backspace / Delete 清除（不用这个快捷键）。录制时先把全部全局快捷键注销（否则按下 Shift+F1 会直接开始截图），窗口失去焦点也会结束录制并恢复。冲突分三种：和另一项重复（前端当场拦下，Rust 注册时再查一遍）、和贴图「鼠标穿透」键 Ctrl+Shift+X 重复、系统注册失败（被别的程序占用）——前两种不保存，第三种照样保存但标红，那个程序退出后重启 SnapMind 就生效。
- **M10.1 历史记录页先不显示缩略图**：缩略图文件要通过自定义协议给页面（没有开放 asset 协议），和保留方式、空间统计一起在 M10.3 做；现在贴图历史显示来源、尺寸、时间和识别出的文字。
- **M10.1 截图格式的说明**：设置里的格式只影响保存；复制到剪贴板始终是 PNG（无损，聊天软件和文档都认），这一点写在格式那一行的说明里，避免误会。
- **M9.2 不附带 ffmpeg**：编程计划原定 ffmpeg（MP4）+ gifski（GIF），改为 MP4 用 Windows 自带的 Media Foundation（`IMFSinkWriter`：H.264 + AAC，`MF_READWRITE_ENABLE_HARDWARE_TRANSFORMS` 打开后有显卡编码器就用显卡）、GIF 用 `gif` crate。ffmpeg 精简版也有几十 MB，而安装包才 9 MB；Media Foundation 每台 Windows 10 / 11 都有（N 版系统要装媒体功能包）；gifski 是 AGPL 许可，它的画质优势在照片类内容上，屏幕录像用不上。系统声音本来就得用 WASAPI loopback（ffmpeg 在 Windows 上录不了系统声音）。Linux（M12）再看 PipeWire / GStreamer。
- **M9.2 编码参数**：H.264 Main，码率按 0.12 bit / 像素 / 帧估算并限制在 2–40 Mbps（屏幕内容细节多，比一般视频给得高）；宽高取偶数（多一列 / 一行就去掉）。AAC 48 kHz（设备是 44.1 kHz 就用 44.1）立体声 192 kbps，多声道只取前两个、单声道复制、其他采样率线性插值到 48 kHz。GIF 每帧 NeuQuant 取 256 色，只编码和上一帧不同的最小矩形，相同帧不写、延时并到上一帧，延时按累计时间取整到 10 ms；帧率最多 30（浏览器里 GIF 每帧至少 20 ms）。
- **M9.2 时间轴**：录制时间 = 从编码器准备好算起、扣掉暂停的时间；每帧的时间戳就是抓到它的录制时间，所以编码跟不上时丢的帧只是少了，不会让视频变快。声音的时间按已写的采样数算；loopback 在没声音时什么都不给，落后录制时间 100 ms 以上就补静音。停止时先把时钟停住，收尾慢也不会拉长最后一帧。
- **M9.2 鼠标指针**：录屏要看到操作，抓帧时用 `GetCursorInfo` + `DrawIconEx` 把当前指针画上去（截图仍然不带指针）。
- **M9.2 保存与提示**：「停止后保存」不弹对话框，直接按截图的默认目录和文件名模板保存，并把文件放进剪贴板（资源管理器、聊天软件里直接粘贴）；遮罩先保留 1.4 秒显示「已保存」，然后结束截图——遮罩一结束就没有地方显示提示了，又不想为此加系统通知。放弃（Esc）删掉文件、回到截图编辑态。截图意外结束（Alt+F4）时保留已经录到的内容。
- **M9.2 透出模式共用**：长截图和录屏的「透出真实画面」抽成 `live.rs`（截屏排除、鼠标穿透切换、其他屏遮罩让开、取消时放回）。录制前的设置阶段仍显示冻结帧，开始录制才透出。
- **M9.1 让页面在遮罩下面滚**：不另开窗口，遮罩原地变成「透明 + 鼠标穿透 + 不被截屏」：冻结帧隐藏，选区里透出真实页面；`SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)` 让每一帧都抓到遮罩下面的内容（Windows 10 2004 起支持）；后台线程每 40 ms 看一次指针，在长截图工具条上时取消穿透、离开时恢复，所以工具条能点、别处的滚轮和点击都落到页面上。键盘焦点留在遮罩上（滚轮不会抢焦点），Enter / Esc 等照常；用户点了页面以后焦点会到页面那边，这时用工具条按钮。
- **M9.1 拼接算法**：行指纹（64 位哈希）投票求偏移，纯色行和在上一帧里出现超过 4 次的行不投票；得票最多的偏移要过两关——投票行里至少一半认同、按它对齐后整段重叠区至少一半的行完全相同（编程计划风险表里的「行哈希 + 模板匹配双重校验」）。上下两端和上一帧逐行相同的部分是页头页尾（最多各占 35%），不参与匹配；用「长图末尾对应上一帧第几行」记账，页尾变高时把已拼进去的几行退回，所以页头页尾都只出现一次、页尾随时可以变。只认向前滚，往回滚或一下滚过整个选区时提示「对不上」并保留上一帧，回到能对上的位置就接着拼。
- **M9.1 滚动条**：行尾 24 像素（选区宽于 200 时）不参与指纹；这一段里每一列按偏移对齐后整列对得上算「跟着滚」，对不上算滚动条，两种对齐都对得上的纯色列不投票；出图时从边上裁到最里面一列滚动条为止（碰到内容列就停）。没有滚动条时不裁。
- **M9.1 自动滚动不用模拟输入**：给选区中心下面的窗口（跳过本程序的窗口）里最深的子窗口投递 WM_MOUSEWHEEL / WM_MOUSEHWHEEL：不用把用户的指针挪进选区，也不受「滚轮发给焦点窗口还是指针下的窗口」设置和系统变暗层吞掉模拟输入的影响（本机实测 SendInput 的滚轮到不了页面，投递消息可以）。每次的量约为选区长度的三分之一（选区短于 300 像素时三分之一格），画面连续两帧不动再滚下一格，连续三次滚了不动就停并提示到底；对不上持续约半秒或到长度上限时也停。不认投递消息的程序（少数 UWP / WinUI）只能手动滚。
- **M9.1 上限与内存**：沿滚动方向最多 30000 像素（够 30 屏，也在常见看图软件和剪贴板能接受的范围内），并且总像素不超过 1.2 亿（宽选区相应缩短）。
- **M9.1 交出去的方式**：复制 / 贴图 / 保存 / 识别文字都结束截图。保存不进 SnapMind 保存窗口（那里预览和估算的是冻结帧），走系统另存为，Ctrl+S 设为直接保存时存到默认目录。识别文字：OCR 会把整张图缩到 1440 以内，长图整张识别字太小，所以沿长边切成约一屏（800–1400 像素）的块、相邻重叠 120 像素，每行按中心归到一块，复制文字并贴出文字卡片（长截图没有可以放识别卡片的冻结帧）。贴图比屏幕的 90% 还大时按比例缩小显示（最小 10%），仍可 Ctrl+滚轮缩放。
- **M9.1 其他**：标注不带进长图（长图里没有冻结帧可画），取消长截图后标注还在；切换纵向 / 横向等于从当前画面重新开始拼；没有单独的「继续滚动」按钮——滚轮本身就是继续，自动滚动按钮可以开关。
- **M8.3 不内置本地公式模型**：评估了需求 12.1 提到的两种和一种轻量替代——PP-FormulaNet（S 版就有 200 MB 以上，官方没有 ONNX，编码器-解码器结构要自己导出并在 Rust 里实现带缓存的自回归解码）、UniMERNet（1 GB 以上）、LaTeX-OCR（约 100 MB，多行和复杂公式明显弱）。安装包 8 MB、OCR 模型 21 MB，为一个低频功能多下载 100–700 MB、每次推理数百毫秒到数秒，不符合「如无必要勿增实体」；视觉大模型对印刷体和手写公式都更准。所以公式只走识别链里的视觉模型，链里没有时提示添加。以后出现 50 MB 以内、有官方 ONNX 的公式模型再接入（命令和卡片不用改，只是在链里多一种后端）。
- **M8.3 公式提示词固定**：和表格一样不进设置——输出要能直接交给 KaTeX：只要公式本身、不要定界符和解释，多行用 aligned，多个公式各占一行。大模型仍常加 ```latex 或 $$，Rust 侧统一剥掉（「$a$ 和 $b$」这种两个行内公式不剥）。
- **M8.3 卡片不分「编辑 / 预览」**：公式通常很短，预览和源码同屏、改动实时渲染最跟手，不需要切换。流式输出时只显示已经能渲染的公式（最后一个常常没写完），不闪错误；完成后写错的公式标红显示源码和原因。
- **M8.3 拆分公式的规则**：按行拆（提示词要求一行一个），begin…end 环境没闭合、花括号没配平、行尾是换行符 `\\` 时与下一行合并。「复制 $$」按这个结果每个公式各包一对，方便粘进 Obsidian。
- **M8.3 KaTeX**：0.16.22（固定版本），trust 关闭（不渲染 href / url / includegraphics / htmlClass 等），只输出 HTML（不带 MathML，DOM 更轻）。字体随 CSS 打包进前端，离线可用。
- **M8.2 Markdown 视图的局限**：Markdown 表格表示不了合并单元格（文字放在左上角那格）；只有用户改了 Markdown 源码才解析回表格，单纯切换视图不会丢失合并信息。
- **调试脚本约定**：给 Windows PowerShell 5 跑的 `.ps1` 只写 ASCII 注释（无 BOM 的 UTF-8 中文注释会吞掉换行，导致下一行代码失效）。
- **MAC-1.3 系统语言与地区**：Mac 上语言读 `NSLocale.preferredLanguages` 的第一项（「语言与地区」里排第一的语言，如 `zh-Hans-CN`，`Language::from_tag` 已能识别 Hans / Hant），不再读 `LANG`——从访达、启动台、登录项启动的程序没有这个环境变量。下载源的地区判断一并改成 `NSLocale.currentLocale.regionCode == "CN"`（和 Windows 读「国家或地区」对应），不跟语言绑定：用中文的人不一定在大陆。验证方法：`open -n /Applications/SnapMind.app --args -AppleLanguages "(zh-Hans-CN)"` 只对这一个进程换首选语言，不动用户的系统设置。
